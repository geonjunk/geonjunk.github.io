  • 회원의 자산과 관련된 기능으로 정확성이 중요하고, 단건씩 지급이 되지만 대량 처리 시 성능 한계가 존재
  • 대량 지급 데이터를 단건 INSERT/UPDATE 방식으로 처리하면 DB Round Trip과 처리 시간 증가
  • 지급 대상자는 사용자 조건 로직을 통해 산정되지만, 실제 지급 시점의 DB 데이터와 불일치할 가능성이 있어 지급 전 비교 검증 로직 필요

해결 방안

  • 쿠폰 및 마일리지 사용자 발급 시 사용자 조건 로직으로 산정된 지급 대상과 실제 DB 기준 지급 가능 대상을 비교하는 교차 검증 로직 추가
  • Validation 로직을 백오피스 API에서 통합 관리
  • 캐시백 및 포인트 일괄 지급 로직에서 지급 대상 데이터를 Chunk 단위로 분할하고, 각 Chunk마다 Bulk INSERT/UPDATE 적용

결과

  • 대량 지급 프로세스의 성능 병목 완화, 지급 대상 산정부터 실제 발급까지 검증 단계를 추가해 오지급·누락·중복 발급 가능성 제거
  • 로그 기반 단위 테스트(nanoTime) 측정 결과 처리 성능 10배 향상

주요 성과

  • Redis MCP 개발로 업무 일관성 및 업무 효율성 증대
    • Cache, Stream, Rate Limit 등 Redis 데이터를 자연어 기반의 일관된 프로세스로 조회·관리할 수 있는 기능 개발
    • 데이터 변경 작업에 사전 검증 절차 적용으로 CUD 작업의 안정성 확보

문제 사항

  • Redis가 cache, ratelimit, stream, nextcache 등 여러 용도로 분리되어 있어 조회 대상 인덱스 선택에 혼동 존재
  • AI 도구에 Redis 접근을 허용할 때 조회와 쓰기 권한을 함께 열어두면 데이터가 변경될 위험 존재
  • 스트림 DLQ 재처리는 Payload 확인 → 원본 스트림 재적재 → DLQ 정리의 반복 절차가 필요

도입 내용

  • FastMCP 기반 Redis 조회 전용 MCP로 자연어 기반 업무별 데이터 조회 기능 제공
  • KEYS 전체 스캔 대신 SCAN 기반 탐색을 사용하고, 운영 환경 조회 전 사용자 확인 절차 구성
  • 조회 결과 반환 전 민감정보 마스킹과 결과 길이 제한을 적용하여 노출 범위 최소화
  • Redis CUD 작업은 Custom Skill로 분리하여 dry-run → 사용자 확인 → apply 흐름을 강제
  • KEYS 기반 일괄 데이터 조작을 스크립트 레벨에서 차단
  • Python 표준 라이브러리 기반 RESP 클라이언트 구현으로 redis-cli나 Docker 없이 Redis 작업 진행
