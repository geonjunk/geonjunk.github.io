  • 트랜잭션 전파레벨을 Requires_new로 설정하여 건별 트랜잭션 분리
  • 오류에 대한 메시징 처리를 명확화하여 컬럼에 저장하고 미처리 건에 대한 별도 처리 기능 개발
결과

  • 고객 업무의 병목을 없애고 생산성 향상

↓ 검증 부족

↓
DB round trip 증가

대량 지급 시 처리 시간이 늘고, DB 기준과 조건 로직 결과가 어긋날 수 있음

TO-BE

캐시백 지급 요청
↓
사용자 조건 로직 대상 산정
＋
DB 기준 지급 가능 대상 조회
↓ 비교 검증
오지급·누락·중복 발급 방지
↓
chunk 분할 → bulk insert/update

검증 단계를 추가하면서도 대량 지급 성능 병목 완화

  • 회원의 자산과 관련된 기능으로 정확성이 중요하고, 단건씩 지급이 되지만 건수가 많아 성능의 한계도 존재
  • 대량 지급 데이터를 단건 insert/update 방식으로 처리하면 DB round trip이 많아지고 처리 시간이 증가한다고 판단
  • 지급 대상자는 사용자 조건 로직을 통해 산정되지만, 실제 지급 시점의 DB 데이터와 불일치할 가능성이 있어 지급 전 비교 검증 로직이 필요하다고 판단

해결 방안

  • 쿠폰 및 마일리지 사용자 발급 시 사용자 조건 로직으로 산정된 지급 대상과 실제 DB 기준 지급 가능 대상을 비교하는 검증 로직 추가
  • validation 로직을 백오피스 API에서 한번에 validation 관리
  • 캐시백 및 포인트 일괄 지급 로직에서 지급 대상 데이터를 chunk 단위로 분할하고, 각 chunk마다 bulk insert/update 쿼리를 적용

결과

  • 대량 지급 프로세스의 성능 병목을 완화하고, 지급 대상 산정부터 실제 발급까지의 검증 단계를 추가하여 오지급·누락·중복 발급 가능성을 제거했습니다.
  • 로그 기반 단위 테스트 측정으로 5배 향상되었습니다. (nanoTime)

마켓플레이스 ↔ 로컬 비교
Git 최신 형상 ↔ 로컬 비교
↓ 차이가 있을 때만
pull / reinstall 자동 실행
↓
리턴값만 출력하여 토큰 사용량 최소화

문제 사항

  • Claude Code를 사용하여 custom MCP나 외부 plugin을 사용할 때 자동으로 업데이트가 되지 않고 일괄 수동 업데이트해야 하는 불편함 존재

도입 내용

  • Python 스크립트 기반으로 MCP, plugin, skill 업데이트하는 Custom skill 도입
  • 마켓플레이스와 로컬 버전을 비교하여 다를 시 업데이트
  • Git 레포의 최신 형상과 로컬 형상을 비교하여 다를 시 pull 및 재설치 커맨드 동작
  • 토큰 사용량 최적화
  • 단순 스크립트를 돌리고 해당 스크립트의 리턴값만 출력하게 하여 출력 토큰 최소화
  • 적은 비용의 모델로 동작하도록 스킬 구성
